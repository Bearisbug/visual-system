# 开发视觉交接

<a id="bd-handoff-001"></a>
## BD-HANDOFF-001 · 品牌规则进入目标平台

- 触发：把现有品牌规则交给开发，输出设计tokens、字体/资产配置、组件视觉与状态示例，或验证目标平台实际消费。
- 规则：以已确认品牌为来源，按下列步骤完成约定平台的视觉交接。
  1. 按 [BD-INPUT-001](design.md#bd-input-001)明确目标平台/工具、实际语言、模式、组件/状态及交付深度。区分独立示例和现有产品接入；已有项目先读取其视觉来源与技术约束。只补会改变当前产物的缺项，不将品牌交接扩大成业务页面、导航或API设计。
  2. 定位当前选稿和品牌参数，按 [BD-SYSTEM-001](system.md#bd-system-001)继承识别、颜色用途、字体及资产条件。传播图的固定画布/字号不是UI尺度；按真实界面文字与交互重新验证排版，保留已定品牌选择。缺正式标志源且本次交付需要时，转 [BD-MASTER-001](assets.md#bd-master-001)补齐；允许的位图展示不因此强制矢量重建。
  3. 按 [BD-TOKEN-001](system.md#bd-token-001)确定交付深度并建立唯一参数源；项目已有参数源时复用并补齐。派生格式由生成器产出，不能在说明、示例和导出分别维护冲突数值。品牌强调与成功/警告/错误等语义用途分开定义；共享色值也不自动互换，状态不能仅靠颜色表达。最小深度只建立本次需要的模式和角色。
  4. 输出目标平台能解释的配置，检查缺失引用、循环、类型/单位与命名冲突。声称DTCG等交换格式时记录实际规范版本、支持范围及目标工具的接入方式；自定义JSON写清自己的合同。格式有效、转换成功、目标工具可消费分别记结果，不能因生成JSON就宣布跨工具兼容。
  5. 依 [BD-TYPE-001](assets.md#bd-type-001)交付字体的真实文件或合法取得入口、family/字重/样式/语言与fallback配置。资产映射记录实际文件、用途、背景、比例、最小尺寸与留白，引用现有母版，不为组件重画另一套Logo。非本次平台所用变体不要求额外生成。
  6. 用交付配置搭建最小的真实消费示例，示例直接引用当前tokens、字体与资产；演示本次组件及其已约定状态，并说明对应触发方式。状态样式由状态层 token 推出：hover、focus、pressed、dragged 是以 currentColor 叠加、透明度读状态 token 的一层；disabled 用元素自身透明度；选中用选中高亮色；焦点环用 outline 与 outline-offset，不用 box-shadow，以免 forced-colors 下消失。文本输入聚焦时只显示焦点环，不叠 focus 层，以免看起来像禁用；`input`、`img` 等替换元素没有 `::after`，状态层放在外层元素上。Web 的状态层 CSS 按 [样例页规格](specimen-spec.md)附录 A 编写，不逐个组件手写状态色。交付完整设计系统或标准组件样例页时，样例页不手搭：写好 `specimen.json` 与品牌片段，运行规格 §8 的渲染器与验收脚本，验收通过后把按节截图交视觉评审。可用本地模拟展示状态，不能把模拟当作业务功能已实现。改现有前端文件时按 ui-constraints 技能执行。现有产品只有完成实际集成与相应验证，才能声明已经接入。
- 产物：开发视觉说明（如`DESIGN.md`）、唯一参数来源、目标格式/配置、资产/字体映射、可运行示例与验证记录。开发配置包可采用自己的逐文件清单，不为满足品牌资产manifest而制造无关母版；随包新增正式Logo/图像资产时再按 [BD-EXPORT-001](assets.md#bd-export-001)与 [BD-DELIVERY-001](assets.md#bd-delivery-001)登记。每个承诺有实际文件与使用入口。
- 落位：在用户项目内交付时，默认写入项目根 `brand/`；一个项目只放一个品牌，不设品牌名子目录。`brand/` 根目录放当前生效的开发交接，至少含开发视觉说明 `brand/DESIGN.md`（写明来自哪个 release 版本，尚无 release 时写明依据的选稿版本）、唯一参数来源 `brand/tokens.json`（模式覆盖在 `brand/modes/`）、生成的目标平台配置（Web 为 `brand/tokens.css` 及适配文件 `tokens.tailwind.css`、`tokens.shadcn.css`，原生平台为该平台的 token 或映射文件）与 resolved 快照；Web 另有状态层 `brand/state-layer.css`，内容即 [样例页规格](specimen-spec.md)附录 A 的 CSS，文件开头把其中的 `--state-*`、`--focus-ring-*`、`--motion-*` 映射到 `brand/tokens.css` 的变量，样例页与产品页面引用同一份；字体配置（如 `@font-face` 声明）放 `brand/fonts/`，交接资产放 `brand/assets/`，验证记录（检查报告、浏览器截图与断言结果）放 `brand/qa/` 随产品仓交付。Web 字体的唯一入口是 `brand/fonts/fonts.css`，其中 `@font-face` 的族名与 tokens 的 fontFamily 一致，`brand/DESIGN.md` 写明它的引入顺序（同一入口样式里紧跟项目所引的 token 文件，`brand/state-layer.css` 排在它之后）。交接示例（组件状态示例、样例页）放 `brand/examples/`，只读取 `brand/` 内的文件；样例页的配置是 `brand/specimen.json`，品牌片段与 `sampleCss` 放 `brand/specimen/`，验收证据放 `brand/qa/specimen/`。开发视觉交接只写 `brand/` 内的文件，接入产品代码按第 6 步交给 ui-constraints。产品仓里做的临时物料（不进 release 的公告图、社媒图等）默认放仓库根 `promo/<slug>/`，不放进 `brand/`；`brand/DESIGN.md` 写一行生效 release 里使用说明文件的路径，供做物料时读取。只读旧参数文件的上游快照（[BD-TOKEN-001](system.md#bd-token-001)第 2 步）放 `brand/upstream/<来源版本>/`，`<来源版本>` 取上游品牌包自己的版本标识（如 `acme-brand-v2`）；快照保持原文件名与内容；每个上游只留当前导入的一份，重新导入时删掉旧版本目录，换成新版本目录。`brand/DESIGN.md` 按该步写明快照路径与漂移检测命令；检测脚本放 `brand/qa/`，只读取 `brand/` 内的文件，只复制 `brand/` 时仍能运行。正式资产 release 放 `brand/releases/<version>/`，过程稿放 `brand/working/`。生效 release 已含本次所需的正式资产或字体文件时，`brand/DESIGN.md` 的资产映射和字体配置直接引用 release 内的文件，不复制进 `brand/assets/` 或 `brand/fonts/`；这两个目录只放 release 之外的文件，如图标、尚无 release 时的 Logo、favicon 与字体文件。品牌在独立仓维护时，各产品仓的 `brand/` 放品牌仓生效 release 的副本，按本字段同一布局存放，`brand/DESIGN.md` 记录品牌仓与版本号；改值先改品牌仓，再整体替换副本。项目已约定其他品牌目录或用户另行指定时从其约定；独立示例写入用户指定目录。已有 `brand/` 时在其中更新受影响文件，不另建第二份品牌目录。
- 验证：在声明的平台、工具/运行时版本下实际加载或导入，检查最终绑定值、真实字体/语言、资产比例/背景、文本可读性及承诺状态。Web以真实浏览器核对计算样式、资源和键盘/指针状态；原生或设计工具使用其真实消费机制，不能用Web截图代替。按 [BD-QA-001](assets.md#bd-qa-001)分别记录机械、运行与目检，保留失败和未测项；上游或适配改变时更新受影响配置与证据，不沿用失效结果。
- 边界：平台未定时可以完成可独立确定的品牌映射并列出具体缺项；不得把待定平台记为通过。只交付静态规则/参数的委托按约定范围完成，运行接入保持未验证；品牌有深色物料不等于产品暗色模式已经具备。
